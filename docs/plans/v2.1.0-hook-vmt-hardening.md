# Libmem.NET 2.1.0 Hook / VMT Hardening Plan

Status: planned  
Target: Windows x64 / .NET 8  
Compatibility baseline: Libmem.NET 2.0.0

## Objective

Harden the existing Hook and VMT wrappers without redesigning the public API or adding application/game-specific patch systems.

## Baseline audit

### HookManager / HookHandle

Current implementation already:

- installs through the session-bound target;
- converts a definite `LM_HookCodeEx` failure into `LibmemException`;
- exposes Source, Destination, Trampoline, PatchedBytes, IsInstalled, and IsDisposed;
- preserves ownership when explicit unhook fails;
- treats successful removal/disposal as idempotent;
- does not unhook from the finalizer thread;
- treats an exited remote target as no longer capable of retaining the installed hook.

Gaps to validate or harden:

- zero / bad source and destination addresses;
- duplicate or overlapping source hooks;
- invalid/non-executable destinations;
- install failure atomicity;
- unhook failure retry behavior;
- process-exit behavior with an active handle;
- external-process runtime coverage;
- instruction-boundary and relative-control-flow coverage.

### VmtManager

Current implementation already:

- rejects a zero VTable address;
- supports Hook / Unhook / GetOriginal / Reset;
- explicitly restores tracked entries during Dispose;
- avoids calling the pinned upstream reset/free path with a non-empty hook list;
- never restores entries from the finalizer thread;
- rejects operations after disposal.

Gaps to validate or harden:

- duplicate Hook on one index;
- Unhook of an untracked index;
- Reset followed by reuse;
- large/invalid index behavior;
- zero/bad replacement address;
- partial restore failure state;
- clearer consumer documentation for local-process-only lifetime requirements.

## Implementation phases

### Phase 1 — Contract tests first

Extend `Libmem.NET.HookVmtTests` before changing implementation behavior.

Add cases for:

- invalid addresses;
- duplicate installs;
- repeated Remove/Dispose combinations;
- VMT duplicate/unknown indices;
- Reset and reuse;
- failure-state invariants.

### Phase 2 — External-process Hook target

Extend or reuse `Libmem.NET.TestTarget` with a stable native-callable test function/page so HookManager can be tested against another process.

Validate:

- install;
- trampoline metadata;
- removal;
- target exit while handle is active;
- cleanup state after exit.

### Phase 3 — Minimal implementation hardening

Only add managed validation or state handling when a test demonstrates a missing contract.

Rules:

- preserve 2.0.0 public signatures unless a new additive API is clearly justified;
- do not duplicate native libmem relocation logic;
- preserve static facade compatibility semantics;
- do not add global liveness preflights to hot paths.

### Phase 4 — Documentation and sample

Update:

- `docs/API.md`;
- XML IntelliSense;
- Hook consumer sample;
- changelog.

Document exactly what is owned, what may throw, what is idempotent, what happens when the target exits, and what is local-process-only.

### Phase 5 — Acceptance

Required gates:

1. Release x64 build;
2. source-contract checks;
3. Public API baseline;
4. self-process Hook/VMT runtime tests;
5. external TestTarget runtime tests;
6. consumer sample;
7. local NuGet PackageReference restore/build/run.

## Non-goals

2.1.0 does not implement:

- Harmony compatibility;
- Mono method resolution;
- Unity/Hearthstone integration;
- managed patch attributes/prefix/postfix/transpilers;
- game state, snapshots, events, IPC;
- x86 release support.

Those features belong in consuming projects or later independent work.
