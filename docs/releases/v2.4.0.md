# Libmem.NET 2.4.0 — Release Candidate Notes / 发布候选说明

> **Candidate only — not published.** The released stable version remains **2.3.0** until the exact 2.4.0 candidate commit passes the release dry run, a `v2.4.0` tag is created, GitHub Release artifacts are verified, and the separate NuGet Trusted Publishing run succeeds.
>
> **仅为发布候选，尚未发布。** 在 2.4.0 指定提交通过发布预演、创建 `v2.4.0` 标签、验证 GitHub Release 产物并完成独立 NuGet Trusted Publishing 前，公开稳定版仍为 **2.3.0**。

## English

Libmem.NET 2.4.0 adds two backward-compatible managed API helpers to the standalone rdbo/libmem C++/CLI wrapper for **Windows x64/x86 and .NET 8**.

### New APIs

- **`AssemblyManager.ReadAlignedCode(ulong address, ulong minimumLength)`** reads a whole-instruction-aligned span from the attached target through existing `CodeLength` and `ReadMemory` operations. Zero requested length yields an empty byte array; oversized requests are rejected, and a failed code-length computation or incomplete read is surfaced as `LibmemException`. This is a read-only inspection helper, not an atomic snapshot, safe instruction relocation or patch installation API.
- **`SymbolManager.TryFindAddress(ModuleInfo module, string name, bool demangle, out ulong address)`** reports an ordinary native symbol miss with `false` and `address = 0`. Argument errors, foreign/stale module identities and disposed sessions remain errors; the existing `FindAddress` native-sentinel contract is unchanged.

### Regression and consumer coverage

- Added x64/x86 self-process and external-process inspection and symbol lookup coverage, including null arguments, foreign-module identity and managed-length bounds.
- Extended Hook/VMT regression checks to validate original bytes after unhook and the instruction-aligned source span without changing patch, ownership or trampoline semantics.
- Added C# examples for enumerated export lookup, guarded read-only instruction inspection and explicit `HookHandle.Remove()` ownership.
- Local candidate NuGet consumers exercise the new APIs; the separate public-feed smoke continues to target the already published **2.3.0** until 2.4.0 has been released.

### Compatibility

- Existing 2.3.0 public APIs, Hook/VMT/Injector behavior, C++/CLI assembly identity and managed exception boundaries remain supported.
- The native backend remains pinned to rdbo/libmem commit `a07c9942bf1358dabcc83eb0cd072736c749d7f8`; this release does not upgrade its ABI.
- Supported targets: **Windows x64 / Windows x86 / .NET 8** with explicit architecture selection.
- Unsupported: AnyCPU, ARM64, Linux, macOS, cross-bitness operations and any application/game-specific abstractions.
- Trampoline relocation safety for location-sensitive instructions, overlap between concurrent hooks and target-thread synchronization remain caller/native-backend responsibilities.

### Publication sequence

1. Pass the 2.4.0 candidate PR's Release x64, Release x86, Public API baseline, native coverage audit and dual-arch NuGet consumer checks.
2. Merge the candidate and pass the main-branch CI on the exact merge commit.
3. Create `release/v2.4.0` at the accepted commit; validate both manifests, matching commit and pinned native SHA, runtime ZIPs, SHA-256 checksums, exact-version NuGet package and generated release notes **without publishing**.
4. Create the matching `v2.4.0` tag only after successful dry run; verify published GitHub artifacts.
5. Manually run Tagged Release with `publish-nuget` enabled, then validate the published NuGet package on x64/x86 and update public smoke baseline and stable docs in a follow-up PR.

## 简体中文

Libmem.NET 2.4.0 面向 **Windows x64/x86、.NET 8**，在独立、通用的 rdbo/libmem C++/CLI 封装层新增两个向后兼容的托管 API。

### 新增 API

- **`AssemblyManager.ReadAlignedCode(address, minimumLength)`**：结合现有 `CodeLength` 和目标进程 `ReadMemory`，只读地获取覆盖指定最小长度的完整指令字节。长度为零时返回空数组；请求过大、指令长度计算失败和不完整读取均有明确的异常处理。它不是原子快照、指令重定位器或自动补丁安装器。
- **`SymbolManager.TryFindAddress(module, name, demangle, out address)`**：常规符号未找到时返回 `false`，并设置 `address = 0`；参数错误、外部/失效模块身份以及已释放的会话仍按原有契约报告错误。旧 `FindAddress` 的 native sentinel 语义保持不变。

### 测试与示例

- 增加 x64/x86 自身进程、外部进程、空参数、模块身份及内存读取长度边界回归测试。
- 验证 Hook 卸载后的原始字节与完整指令边界；不改写 Hook、VMT、Injector 实现。
- 补充 C# 符号查找、只读指令检查和显式 `HookHandle.Remove()` 生命周期示例。
- 本地候选 NuGet 消费者覆盖 2.4.0 新接口；公网 NuGet Smoke 在新版正式发布前仍验证 2.3.0。

### 兼容与限制

- 保留 2.3.0 已公开 API、异常、Hook/VMT/Injector 语义，不进行破坏性改动。
- 固定 rdbo/libmem commit `a07c9942bf1358dabcc83eb0cd072736c749d7f8`，不升级原生 ABI。
- 仅支持 **Windows x64/x86 + .NET 8**，并要求显式选择架构；不支持 AnyCPU、ARM64、Linux/macOS 和跨位数操作。
- 相对跳转等位置敏感指令的 trampoline 安全性、Hook 重叠冲突与目标线程同步仍需调用方自行评估。
- 不引入 Hearthstone、Unity、Mono、GameState、Snapshot、IPC 或其他业务层功能。

### 正式发布条件

完成候选 PR CI、合并后主线 CI、`release/v2.4.0` 发布预演、双架构 ZIP 和 SHA-256/manifest/提交来源验证后，才能创建 `v2.4.0` 标签；随后独立执行 NuGet OIDC 发布及公网 x64/x86 消费者验收。发布完成后进入阶段性稳定性维护。
