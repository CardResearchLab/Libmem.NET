> **尚未公开发布的候选版。** 源码版本号和本地 CI 产物并不代表已在 GitHub Release 或 nuget.org 上架；正式稳定版仍为 2.3.0。

## English

Libmem.NET 2.4.0 is a backward-compatible Assembly/Symbols enhancement to the independent rdbo/libmem C++/CLI/.NET 8 wrapper for **Windows x64 and x86**.

### New managed APIs

- `AssemblyManager.ReadAlignedCode(ulong address, ulong minimumLength)`: determine an instruction-aligned target-memory span through the existing native `CodeLength` API, then read the complete span through the bound process session. A zero-byte request returns an empty array. Oversized managed ranges throw `ArgumentOutOfRangeException`; failed alignment or incomplete memory reads throw `LibmemException`.
- `SymbolManager.TryFindAddress(ModuleInfo module, string name, bool demangle, out ulong address)`: returns `true` and the resolved address for a match, or `false` and address zero for a normal native bad-address miss. Null arguments, foreign module identities and disposed-session errors still throw. Existing `FindAddress` sentinel behavior is unchanged.

### Regression coverage and examples

- Self-process, external-process, x64/x86, Hook/VMT and independent local NuGet consumer tests exercise the new APIs and existing compatibility contracts.
- C# samples demonstrate symbol enumeration/lookup and read-only instruction inspection around explicitly owned hook installation and removal.
- `ReadAlignedCode` does **not** perform machine-code relocation, patch installation, memory-protection changes, atomic snapshots or thread synchronization. Trampoline behavior and lifetime remain governed by existing Hook APIs.

### Compatibility and publication gates

- Additive public managed API only; no changes to existing 2.3.0 members or Hook/VMT/Injector semantics.
- No pinned rdbo/libmem revision change, native ABI upgrade, ARM64, Linux, macOS, AnyCPU or cross-bitness support.
- Before publishing: exact 2.4.0 x64/x86 Release builds; Smoke, ExternalProcess, Hook/VMT, Injector and Public API baseline checks; ZIP/checksum/provenance validation; local-feed x64/x86 NuGet consumer tests; release-branch dry run; tagged GitHub Release; manually enabled NuGet Trusted Publishing; public-feed x64/x86 smoke.
- Build #418/#419 verified PR #129; Build #421/#422 verified PR #132 and merged main. **These checks are not a substitute for the final exact-version release candidate and tag checks.**

## 简体中文

Libmem.NET 2.4.0 是面向 **Windows x64/x86、.NET 8** 的通用 rdbo/libmem C++/CLI 封装库的向后兼容 Assembly/Symbols 更新。

### 新增托管 API

- `AssemblyManager.ReadAlignedCode(ulong address, ulong minimumLength)`：调用既有 `CodeLength` 计算覆盖最小字节数的完整指令跨度，并通过绑定的目标进程会话读取全部字节。请求长度为零时返回空数组；超出托管数组容量时抛出 `ArgumentOutOfRangeException`；指令边界计算失败或读不全时抛出 `LibmemException`。
- `SymbolManager.TryFindAddress(ModuleInfo module, string name, bool demangle, out ulong address)`：找到符号时返回 `true` 及地址，正常未找到时返回 `false` 且输出地址置零；空参数、跨进程模块身份以及已释放会话等错误仍抛异常。既有 `FindAddress` 的 native 哨兵值语义保持不变。

### 测试与使用示例

- 覆盖自进程、外部进程、x64/x86、Hook/VMT 和独立本地 NuGet 消费者的回归验证。
- C# 示例演示原生符号查找，以及在明确拥有 HookHandle 的安装与卸载生命周期中进行只读指令检查。
- `ReadAlignedCode` **不是** 指令重定位引擎、自动 Patch 安装器、内存保护修改器、原子快照或线程同步机制；trampoline 与资源所有权仍遵循既有 Hook API。

### 兼容性与发布验收

- 仅增加托管 Public API；不改变 2.3.0 已有接口与 Hook/VMT/Injector 行为。
- 不升级固定 native libmem，不修改 ABI，不支持 ARM64、Linux、macOS、AnyCPU 或跨位数操作。
- 发布前必须完成 2.4.0 精确版本的双架构 Release 构建、Smoke / ExternalProcess / Hook/VMT / Injector / Public API 校验、ZIP 与 SHA-256/来源审计、双架构本地 NuGet 消费、release 分支 dry run、tag 对应 GitHub Release、人工启用 OIDC NuGet 发布与公网消费验收。
- PR #129 的 Build #418/#419、PR #132 的 Build #421/#422 已通过；但**不能代替**候选版本和 tag 的最终验收。
