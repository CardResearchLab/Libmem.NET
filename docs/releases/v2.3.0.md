# Libmem.NET 2.3.0 — Release Notes / 发布说明

> **Stable release:** Published to GitHub and nuget.org on 2026-10-08. Release commit: `561bf1dfa82b7df2da4dc649a016c103f3af71ff`. Public x64/x86 NuGet consumer smoke #30 passed.
>
> **正式稳定版：** 已于 2026-10-08 发布至 GitHub 和 nuget.org，发布提交为上述 commit；公网 x64/x86 NuGet 消费测试 #30 已通过。

## English

Libmem.NET 2.3.0 is a backward-compatible enhancement to the general-purpose rdbo/libmem C++/CLI wrapper for **Windows x64/x86 and .NET 8**.

### New managed APIs

- `MemoryManager.ReadInt64` / `WriteInt64`: read/write complete 8-byte signed values.
- `MemoryManager.ReadPointer` / `WritePointer`: use **target ProcessSession bitness** (4 bytes for x86, 8 for x64); reject pointer values above `uint.MaxValue` on x86 instead of truncating.
- New typed operations throw `LibmemException` for incomplete memory transfers. Existing `Read` and `Write` retain their original partial-transfer result behavior.

### Native coverage

- `eng/audit-native-api.py` checks function references against pinned `libmem.h` as part of source/contract CI.
- There are 71 upstream native C API functions, 69 direct references in the wrapper implementation, and 2 intentional managed command-line alternatives (`LM_GetCommandLine` and `LM_FreeCommandLine`). See `docs/API_COVERAGE.md`.
- This is a native reachability audit, not an assertion that every C signature maps to one distinct managed public method.

### Compatibility and release constraints

- Existing 2.2.1 Public API signatures are preserved; four methods are additive.
- No pinned native libmem update, ARM64, Linux, macOS, game-specific APIs, or IPC.
- Continue requiring explicit x64/x86 platform selection; AnyCPU and cross-bitness operation are unsupported.
- Release validation completed: Windows x64/x86 Release builds, external-process suites, Hook/VMT and Injector regressions, runtime ZIP SHA-256/provenance checks, multi-architecture NuGet consumer tests, and post-publication nuget.org smoke. GitHub Release #42 and tagged OIDC publication #43 both succeeded.

## 简体中文

Libmem.NET 2.3.0 是面向 **Windows x64/x86、.NET 8** 的通用 rdbo/libmem C++/CLI 封装库向后兼容更新。

### 新增托管 API

- `MemoryManager.ReadInt64` / `WriteInt64`：严格按 8 字节完整读写 64 位有符号整数。
- `MemoryManager.ReadPointer` / `WritePointer`：根据**目标 ProcessSession 的进程位宽**读写指针，x86 使用 4 字节，x64 使用 8 字节；x86 遇到超出 `uint.MaxValue` 的地址时抛出异常，不做静默截断。
- 类型化操作遇到不完整的内存读写抛出 `LibmemException`；原来的 `Read` / `Write` 保持短读写返回语义。

### native API 覆盖审计

- 新增 `eng/audit-native-api.py`，在 CI 中对固定版本的 `libmem.h` 执行 API 覆盖检查。
- native C API 共 71 个函数；69 个由 C++/CLI 源码直接调用，2 个命令行函数由于固定版本上游 Windows 实现的已知问题，采用托管替代方案；具体见 `docs/API_COVERAGE.md`。
- 这里是 native 引用覆盖审计，并不代表每个 native 函数都有独立同名的 Public API。

### 兼容性与发布规则

保持 2.2.1 已有 Public API、native 版本和 Windows x64/x86 双架构支持不变。不包含 ARM64、Linux/macOS、Unity/Mono 或业务层能力。

2.3.0 已完成双架构构建、运行时/外部进程/Hook/VMT/Injector 回归、ZIP/校验文件、NuGet 消费者验证。GitHub Release #42 与 OIDC NuGet 发布 #43 均成功，公网 x64/x86 回归测试 #30 通过。
