## English

Libmem.NET 2.4.1 is a backward-compatible stability-only patch to the general-purpose rdbo/libmem C++/CLI wrapper for **Windows x64/x86 and .NET 8**.

### Fixes

1. **`AssemblyManager.ReadAlignedCode` at page boundaries.** When a complete instruction occupies the last readable bytes before a `PAGE_NOACCESS` page, the native code-length fast path can fail due to a wider probe. A bounded fallback reads only accessible bytes and decodes complete instructions; incomplete instructions and inaccessible data continue to fail. Existing `CodeLength` semantics are unchanged. Covered by two-page regression tests on x64 and x86 (PR #137).
2. **Process identity before remote mutation.** Validate both PID and process start time before remote `FreeMemory`, `AllocateMemory`, `ProtectMemory`, `HookCode`, `LoadModule` and `UnloadModule` paths, including the corresponding session Managers. Deterministic external-process tests simulate stale identities without requiring real-world PID reuse (PRs #138–#140).
3. **Reliable Hook removal regression.** The failure-path test for `HookHandle.Remove` now sets its still-allocated trampoline to `PAGE_NOACCESS`, rather than freeing it and assuming Windows will not reuse that address. It checks that the trampoline is unreadable before attempting removal and verifies the source behavior and protection remain unchanged on failed removal (PR #141).

### Compatibility

- No added public API members or intentional public behavior break, namespace migration, native libmem revision change, or ABI update.
- Supported targets remain **Windows x64/x86 and .NET 8** with explicitly selected architectures. AnyCPU, ARM64, Linux, macOS and cross-bitness operation remain unsupported.
- No Hearthstone, Unity, Mono, IPC or game-specific features are included.

### Known limit

The new process-identity checks are **preflight checks**, not atomic process-handle-bound operations. Native libmem currently reopens certain targets by PID. A target can exit and its PID be reused after the preflight but before the native operation. This time-of-check/time-of-use race is **not fully resolved** by 2.4.1. A handle-bound native redesign would require separate review and testing.

## 简体中文

Libmem.NET 2.4.1 是面向 **Windows x64/x86、.NET 8** 的通用 rdbo/libmem C++/CLI 封装库的向后兼容稳定性补丁版本。

### 修复内容

1. **`ReadAlignedCode` 内存页边界问题。** 完整指令位于可读页末尾、下一页为 `PAGE_NOACCESS` 时，native `CodeLength` 因较宽的探测读取可能失败。现增加有界回退读取，仅解码实际读取到的完整指令；不完整指令、不可读范围仍按原有错误规则处理，`CodeLength` 自身行为不变。增加 x64/x86 双页回归测试（PR #137）。
2. **远程修改前的进程身份校验。** 在远程内存释放/分配、页权限修改、Hook 安装、模块加载/卸载等操作中校验 PID 与进程创建时间，并覆盖相应会话 Manager。使用确定性外部进程测试模拟过期身份，无需依赖真实 PID 复用（PR #138–#140）。
3. **Hook 卸载失败路径测试稳定化。** 将仍处于分配状态的 trampoline 页面设置为 `PAGE_NOACCESS`，不再依赖释放后的地址不被 Windows 复用。先确认跳板不可读，再检查 `HookHandle.Remove` 的失败结果及原始代码行为、保护属性是否保持不变（PR #141）。

### 兼容性

- 不增加 Public API，不进行命名空间迁移或有意引入破坏性变化，不升级固定 native libmem 版本或 ABI。
- 继续仅支持 **Windows x64/x86、.NET 8**，必须显式选择架构；不支持 AnyCPU、ARM64、Linux、macOS 或跨位数操作。
- 不引入炉石、Unity、Mono、IPC 或游戏业务逻辑。

### 已知局限

新的进程身份校验是**操作前预检查**，不属于与原生进程句柄绑定的原子操作。部分 native libmem 接口仍按 PID 重新打开目标；目标可能在校验后、原生调用前退出，随后发生 PID 复用。因此 **2.4.1 尚未彻底消除 TOCTOU 竞态**。未来若改为句柄绑定的 native 设计，需要单独审查和完整测试。
