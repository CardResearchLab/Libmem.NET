# LibmemCli v1.0.0

> Historical release before the Libmem.NET identity migration. Asset and assembly names remain `LibmemCli`; this archive does not describe current main or authorize republication.

Released: **2026-09-30**

LibmemCli v1.0.0 is the first stable release of the general-purpose **Windows x64 / .NET 8 C++/CLI wrapper for rdbo/libmem**.

## Release positioning

v1.0.0 completes the Windows x64 API freeze and establishes the supported public managed contract for the v1.x line.

The release is intentionally focused on wrapper responsibilities:

- native-to-managed API mapping;
- process, thread, module, symbol, segment, memory, scan, assembly/disassembly, Hook/VMT, and injection APIs;
- managed type conversion and validation;
- deterministic ownership/lifetime wrappers;
- native failure to managed exception mapping where the contract defines a definite failure;
- Windows x64 packaging, runtime verification, and consumer documentation.

Application-specific Snapshot, Entity, GameState, IPC, Unity, Mono, Hearthstone, and other product logic are deliberately outside LibmemCli.

## Highlights

### Stable session-oriented API

`ProcessSession` is the recommended aggregation root:

| ProcessSession property | Manager |
| --- | --- |
| `Memory` | `MemoryManager` |
| `Modules` | `ModuleManager` |
| `Threads` | `ThreadManager` |
| `Scanner` | `ScanManager` |
| `Symbols` | `SymbolManager` |
| `Assembly` | `AssemblyManager` |
| `Hooks` | `HookManager` |
| `Injector` | `InjectorManager` |

The static `Libmem.*` facade remains available as the lower-level compatibility surface.

### Stable ownership semantics

v1.0.0 freezes deterministic ownership behavior for:

- `RemoteAllocation`;
- `HookHandle`;
- `VmtManager`;
- `InjectedModuleHandle`.

Explicit disposal performs deterministic cleanup or surfaces cleanup failure. Finalizers do not perform dangerous remote memory, code, VMT, or loader restoration operations.

### Stable result and failure contracts

The release distinguishes between normal misses, native-style sentinels, invalid managed arguments, and definite native failures.

Examples:

- process/module/segment lookup miss → `null`;
- symbol/scan/deep-pointer miss → libmem bad-address sentinel;
- definite Manager operation failure → `LibmemException` where documented;
- invalid managed arguments → standard .NET argument exceptions.

### Process identity safety

Process-sensitive objects and sessions use PID plus process start-time identity where required to reject PID reuse and cross-process descriptor misuse.

`ModuleInfo` carries internal process provenance without expanding its public read-only surface.

### Runtime validation

The v1.0 line is covered by:

- Build + Runtime Smoke;
- Hook/VMT Runtime Tests;
- Injector Runtime Tests;
- External Process Runtime Tests;
- independent NuGet PackageReference consumer validation;
- committed public API baseline checks;
- pinned upstream libmem public-API coverage checks.

## Supported platform

Official stable target:

```text
OS:            Windows
Architecture:  x64
Managed:       .NET 8
Native:        pinned rdbo/libmem
```

x86 remains deferred/best-effort source compatibility and has no v1.0.0 release asset.

Cross-bitness injection is not supported.
