## English

### Highlights

- **Scanning:** `ScanManager.TryDataScan`, `TryPatternScan`, and `TrySigScan` return `true` plus the matching `out ulong` address. Normal misses return `false` and zero. Existing scan methods keep their native bad-address sentinel contract.
- **Memory I/O:** `MemoryManager.TryRead` reports a complete read or an ordinary short read while preserving the bytes read; `TryWrite` reports the full/short-write result and actual byte count. Zero-length requests succeed. A partial write is not rolled back.
- **Hook lifecycle:** Static local-process `HookHandle.Remove()` preflights the trampoline through a safe self-process read before entering pinned `LM_UnhookCode`. An unreadable trampoline now returns `false` without discarding ownership; callers can repair access and retry.
- **VMT regression:** Multi-entry `Reset()` covers a partial restore, inaccessible slot, retained bookkeeping and subsequent successful retry. The VMT implementation remains unchanged.

### Compatibility

- Windows **x64 and x86**, **.NET 8**, and architecture-matched C++/CLI/native binaries.
- No removed or changed existing managed API signatures compared to `v2.4.1`; **five additive public methods**.
- No change to the pinned `rdbo/libmem` native commit `a07c9942bf1358dabcc83eb0cd072736c749d7f8`.
- AnyCPU, ARM64, Linux/macOS, cross-bitness and application/game-specific functionality remain unsupported.
- Hook removal remains non-atomic, including races between read preflight and native patching. Trampoline relocation remains limited by pinned libmem; this release does not promise arbitrary instruction relocation safety.
- PID/start-time identity prechecks reduce but do not eliminate PID-reuse and check-to-use races.

## 中文

### 新增与修复

- **内存扫描：** `ScanManager.TryDataScan`、`TryPatternScan`、`TrySigScan` 返回布尔命中结果与输出地址。普通未命中返回 `false` 且地址为 0；原扫描接口仍保留 native 地址哨兵。
- **内存读写：** `MemoryManager.TryRead` / `TryWrite` 用 `bool` 判断是否完整传输，并保留实际读取字节和已写字节数量。长度为零的有效操作成功；短写入不自动回滚。
- **Hook 生命周期：** 本进程静态 Hook 卸载前预检 trampoline 可读性。预检失败时不丢失 Hook 资源所有权，支持修复后重试。
- **VMT：** 增加多条目 Reset 部分恢复失败后再次恢复的回归测试，不修改原生 VMT 代码。

### 兼容性边界

- 正式支持 Windows x64/x86、.NET 8，托管/原生架构必须匹配。
- 与 `v2.4.1` 比较，仅增加 **5 个**公开方法，不删除或更改已有方法签名。
- 固定的原生 libmem 提交不变，不增加游戏业务、IPC、Unity/Mono 等功能。
- 不支持 AnyCPU、ARM64、跨位数或 Linux/macOS。Hook 卸载仍非原子，原生 trampoline 重定位能力存在固有限制。
- 进程身份预检查无法完全消除 PID 复用与检查到使用之间的竞态。
